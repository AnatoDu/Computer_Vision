# Git: короткая рабочая шпаргалка

На первом занятии Git не блокирует работу: [ПЕРВЫЙ_СТАРТ.md](ПЕРВЫЙ_СТАРТ.md). Если его нет — обычные файлы и резерв. GitHub нужен к следующему занятию; первое размещение через сайт допустимо.

## Папки

Скачайте курс через Git clone или Download ZIP и скопируйте project_template целиком в свою рабочую папку с любым именем. Готовый архив cv_project уже содержит этот шаблон. Не инициализируйте вложенный репозиторий внутри клона курса. Работайте в своём workbooks: course_support с проверками и данными уже рядом внутри проекта. Репозиторий преподавателя для запуска не нужен.

Рабочая папка может находиться в любом доступном вам месте. Используйте свою копию проекта и проверяйте сохранение. Общее хранилище не считайте приватным; отдельная резервная копия нужна независимо от расположения рабочей папки.

## Когда Git уже установлен

В терминале, **внутри своей папки проекта** (а не курса):

```bash
git init -b main
git config user.name "Ваше имя или ник"
git config user.email "ваша почта или GitHub noreply"
git status
git add .
git commit -m "Первый результат"
```

Не запускайте init заново в чужой или уже существующей папке. Старый Git без `-b`: `git init`, затем `git branch -M main`. Настройки name/email локальные, без `--global`. Перед add проверьте, какие файлы попадут в коммит; дополнительные файлы добавляйте осознанно.

## На своём устройстве: GitHub

Создайте пустой репозиторий без README, если локальный проект уже существует. Подключите его адрес и отправьте коммиты:

```bash
git remote add origin <адрес-вашего-репозитория>
git push -u origin main
```

Если origin уже есть, сначала `git remote -v`, не заменяйте его вслепую. Если репозиторий создан через сайт и уже содержит README, начните с `git clone <адрес>` и перенесите в клон свои файлы: это проще конфликтующего объединения двух историй.

На общем компьютере сегодня не настраиваем вход GitHub/токены. На своём устройстве используйте штатный вход GitHub. Пароль аккаунта не является паролем HTTPS для Git. Учебный результат можно сначала загрузить через сайт; это не требует локального Git.

## Перенос работы без входа в GitHub

Сначала Ctrl+S и `git status`, затем коммит нужных файлов. Если нужен перенос истории:

```bash
git bundle create ../cv_project.bundle --all
```

Для восстановления в **новую** папку: `git clone <путь-к-файлу.bundle> <новая-папка>`. Проверьте, что последняя работа есть. Bundle не включает незакоммиченные и игнорируемые файлы, поэтому не заменяет проверку содержимого копии. Для переноса простых файлов Git не нужен.

При dubious ownership не устанавливайте `safe.directory *`: попросите проверить конкретный путь. При конфликтах/ошибках не выполняйте reset/restore/delete по догадке — сначала сохраните свою работу и покажите сообщение. Не пытайтесь чинить все технические проблемы за счёт времени практики.

Обновление учебных материалов без потери ответов описано в [ПЕРВЫЙ_СТАРТ.md](ПЕРВЫЙ_СТАРТ.md). В своём репозитории pull получает **вашу** работу с GitHub, а не новые задания преподавателя.
