# ЛР3. Классическое компьютерное зрение

Связать методы блоков 05–07 в воспроизводимый эксперимент. Максимум — 15 баллов,
срок объявляет преподаватель. Своя камера, GPU, GitHub и установка OpenCV не обязательны.
Учебных данных достаточно для полного балла. Самостоятельные расчёты на NumPy равноправны
библиотечным реализациям; готовая иллюстрация не заменяет ваш запуск.

## Данные и результат

Используйте учебные изображения и функции из блока 05 для сопоставления и выравнивания,
`course_support/data/video/conveyor.npz` для видео. В `SOURCE.md` описаны происхождение,
размеры, шкалы, временная сетка и известные ограничения. Можно согласовать другой разрешённый
набор со сравнимой задачей и доступным эталоном; усложнение само по себе не добавляет баллов.

Сдайте тетрадь либо несколько тетрадей с инструкцией порядка запуска, результатами,
параметрами, сравнением и короткими выводами. Данные/поддержка или точная инструкция их получения
должны позволять повторить опыт. Файлы/архив равноправны ссылке на репозиторий.

## Что сделать

1. **Точки, пары и геометрия.** Получите особые точки и дескрипторы на учебном примере из 05.1,
   сопоставьте их или предоставленные дескрипторы по схеме 05.2. Покажите ложную/неоднозначную пару
   и правило её отбраковки. Предусмотрите отсутствие достаточного числа надёжных пар.
   Рассчитайте гомографию по четырём проверенным соответствиям; предоставленные углы листа допустимы,
   если явно указано, что они предоставлены, а не автоматически найдены. RANSAC только переноса
   из 05.2 не называйте общим RANSAC гомографии.
2. **Выравнивание.** Примените гомографию к учебному фото документа; покажите исходник, выровненный
   результат и контрольную ошибку на точках. Измените одну размеченную точку или условие съёмки,
   объясните влияние на результат. Ручные соответствия не выдают за автоматический детектор листа.
3. **Видео.** Сначала самостоятельно посчитайте пересечения центра посылки через x=320 вправо
   по предпросмотру/кадрам. Запишите ручной результат и правило события. Затем получите маски,
   рамки, траекторию и программный счёт. Разберите потерю трека, пропуск и возможность повторного
   счёта: в учебном ролике есть остановка и смена света. Рамки генератора используйте только
   для оценки, не в детекторе. Для устойчивого правила можно опереться на упражнения 07.2;
   полноценный многообъектный трекер писать не требуется.
4. **Сравнение.** Примените два варианта к одним кадрам: например, фиксированный фон и фон с общей
   поправкой освещения. Сравните ошибку счёта, средний IoU рамок с пропусками как нулями и время
   одинаковых участков вычисления. Укажите машину, параметры и что вошло в измерение времени.
   Не включайте показ графиков только в один вариант. Плохой результат одного метода полезен,
   если причина разобрана; обязательного порога точности или превосходства нет.
5. **Проверка вывода.** Покажите хотя бы одно условие, в котором ваш вывод перестаёт работать:
   дрожание около линии, большой передний план, тень, перекрытие или другая постановка события.
   Можно использовать небольшой специально построенный контрпример, явно назвав его синтетическим.

## Критерии — прежние 15 баллов

| Критерий | Максимум |
|---|---:|
| Особые точки, сопоставление и гомография; ложные соответствия и неудача поиска обработаны | 4 |
| Документ выровнен, результат и ограничения показаны | 3 |
| Видео посчитано, есть ручное сравнение и разбор пропусков/повторов | 4 |
| Два варианта сопоставлены на одинаковом наборе по качеству и времени | 3 |
| Запуск и промежуточные результаты воспроизводимы | 1 |
| **Итого** | **15** |

Критерии совпадают с [ОЦЕНИВАНИЕ.md](ОЦЕНИВАНИЕ.md). Упражнения и зелёные checks сами по себе
баллов не начисляют. Каскад лиц, HOG-детектор, MOG2 и конкретная библиотека не становятся скрытыми
обязательными требованиями ЛР3. Не публикуйте чужие лица/номера без подходящих условий использования;
для этой работы достаточно предоставленных учебных сцен. Укажите ИИ-помощь и объясните своё решение.
